# 使用说明

安装和启动见 [README](../README.md)。本页说明配置、播放策略和常见问题。

## 配置

首次使用时将 `config.example.json` 复制为 `config.json`；后者是个人配置，不提交到 Git。修改后重启程序生效，相对路径以脚本所在目录为基准。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `ollama_url` | `http://127.0.0.1:11434/api/chat` | Ollama 对话接口 |
| `model` | `qwen3.5:4b-q4_K_M` | 与 `ollama list` 中名称一致 |
| `context_tokens` | `32768` | 32K 上下文；显存紧张可尝试 `16384` |
| `max_output_tokens` | `4096` | 单次回答生成 token 数上限 |
| `tts_model_dir` | `models/kokoro-multi-lang-v1_1` | Kokoro 模型目录 |
| `speaker_id` | `3` | 中文女声 `zf_001` |
| `speech_speed` | `1.0` | 大于 1 更快，小于 1 更慢，可先试 0.9～1.2 |
| `startup_text` | `你好，我在，请问有什么可以帮你？` | 启动后朗读；空字符串关闭，旧配置缺少此项时使用默认值 |
| `tts_threads` | `4` | CPU 合成线程数，可用相同文本比较 4 和 6 |
| `first_chunk_chars` | `32` | 首段没有合适标点时的字符上限，不是等待门槛 |
| `chunk_chars` | `80` | 后续字符上限，控制单段合成时间 |

模型目录需要包含 `model.onnx`、`voices.bin`、`tokens.txt`、`espeak-ng-data/`、`lexicon-us-en.txt` 和 `lexicon-zh.txt`，请保留解压包的完整内容。

### 音色与语速

本项目使用的 Kokoro v1.1 中，中文女声编号为 3～57，男声为 58～102。可用同一段文本、相同语速对比以下声音：

| 音色名称 | `speaker_id` | 类型 |
| --- | --- | --- |
| `zf_001` | `3` | 中文女声 |
| `zf_073` | `40` | 中文女声 |
| `zm_009` | `58` | 中文男声 |
| `zm_010` | `59` | 中文男声 |

完整映射与样例见 [sherpa-onnx 官方试听页](https://k2-fsa.github.io/sherpa/onnx/tts/all/Chinese-English/kokoro-multi-lang-v1_1.html)。音色名称中的数字不等于 `speaker_id`；以上顺序不是质量排名。当前未提供单独的情绪或音高控制。

### 上下文与输出

每次请求显式设置 `num_ctx` 和 `num_predict`，不依赖 Ollama 的默认窗口。发起一轮请求后，可观察实际分配：

```powershell
ollama ps
nvidia-smi
```

`ollama ps` 的 `CONTEXT` 表示分配窗口，`100% GPU` 表示模型完全加载到 GPU；显卡整体占用以 `nvidia-smi` 为参考。32K 窗口能加载不代表长输入的峰值占用和性能已经验证。

系统提示词、历史和本次问题共同占用输入预算，程序为输出上限另留空间。当前按 UTF-8 字节数加格式余量保守估算，超过预算时成对移除最早问答；这不是精确 tokenizer，可能早于实际窗口耗尽时裁剪。

当前关闭思考，不发送思考过程给 TTS。系统提示词和采样参数位于 `chat_tts.py`，不同模型可能需要适配。模型回答达到输出上限时会提示可能未说完。

## 分段播放与延迟

每段最少累计 20 个字符（按 Python 字符串长度计数，包含标点）。首段达到该长度后，遇到句号、问号、感叹号、分号、逗号、冒号或换行就提交合成，无需等到 32 字。“好呀，”等过短开头会与后文合并，避免刚出声就等待下一段。没有合适标点时按字符上限切分；回答结束时即使剩余不足 20 字也会提交，包括整篇回答都不足 20 字的情况。

英文句点需后接空白才识别为句末，数字后面的英文逗号和冒号不作为首段提前切分点。后续片段优先在句末切分，并合并不足 20 字的短句；达到字符上限时优先沿逗号或空格切分，但切分点也必须满足 20 字下限，否则按上限硬切。`first_chunk_chars` 和 `chunk_chars` 均不能小于 20。长句硬切可能影响语调，英文长词也可能被切开。

后续分段上限还会按上一段字符数的 1.5 倍约束，最低 20 字且不超过 `chunk_chars`。这是面向中文、根据此前约 0.49 实时率采用的近似策略，减少短片段之后立即生成长片段的情况；字符数不能精确预测音频时长，仍需实际试听。

同一轮中，一个工作线程顺序合成，一个工作线程顺序播放；当前片段播放期间继续合成下一段。队列限制文本和音频积压，因此长回答的终端输出有时会暂缓刷新，不会因此丢弃片段。

此前串行原型在 i5-10600KF 上的一次故事测量：文本生成 5.95 秒，整篇合成 84.34 秒，音频 173.27 秒，首次播放约需等待 90 秒。合成实时率约为 0.49，说明该次平均合成速度快于播放速度；这不是分段版本的延迟测试结果。

分段可以提前准备首段音频，但不保证降低总合成量。很短的首段可能先播完，再等待下一段；设备波动也可能产生句间停顿。

### 运行指标与音频文件

每轮完成后显示首段文本到达时间、首段提交播放时间、播放段数、累计合成时间、音频长度、实时率和输入/输出 token 数。

“片段间等待”统计上一段播放调用返回到下一段播放调用开始之间的累计时间和最长时间，包含等待合成与准备音频的开销，不包含音频自身的静音或设备缓冲。若听感停顿明显但该指标很小，可回听保存的 WAV，进一步区分合成语音中的停顿和播放设备问题。

首段提交播放时间不包含远程桌面传输和设备缓冲延迟；实时率为累计合成时间除以音频长度，小于 1 表示该轮平均合成快于播放。

最新一轮已播放的片段按顺序保存到 `output/last_reply.wav`。错误或手动退出时文件可能不完整；本轮尚未开始播放时不会覆盖旧文件。实际播放中的等待空隙不写入 WAV。

## 对话与中断

- 仅在完整接收回答并完成本轮播放后更新历史；失败时可能已经播出部分内容，但本轮不写入历史，也不自动重播。
- 历史只存在于内存，不提供摘要或长期记忆；退出后清空。
- 播放完才能输入下一问，不支持语音打断；`Ctrl+C` 会等待当前同步合成或播放结束，并非即时静音。
- TTS 朗读模型原话，不核验事实；开始播放后不能撤回已播出的内容。
- 仅在语音合成输入中去除中文双引号，终端文本和对话历史保留原文。

## 常见问题

**找不到配置文件**：在项目根目录把 `config.example.json` 复制为 `config.json`，然后填写模型目录。更新代码时保留自己的配置。

**找不到模型文件**：检查 `tts_model_dir`，避免多嵌套一层同名目录，并保留解压包的全部资源。

**Windows 解压提示找不到 bzip2**：使用 README 中的 Python `tarfile` 命令，无需系统额外安装 bzip2。

**远程桌面没有声音**：检查远程客户端的音频重定向设置和系统输出设备；打开 `output/last_reply.wav` 对比声音。

**音色没有变化**：确认修改的是当前运行项目的 `config.json`，修改后重启；可对比女声 `3` 和男声 `58` 检查设置是否生效。

**出现 `OOV word skipped`**：词典前端遇到不认识的字符可能跳过。已处理此前发现的中文双引号；普通汉字也被跳过时，应检查模型、词典和实际文本，不要只隐藏日志。

**Ollama 连接失败或找不到模型**：确认后台服务运行且名称与 `ollama list` 一致。默认使用本机接口，无需开放到局域网。

参考：[Ollama Chat API](https://docs.ollama.com/api/chat)、[Ollama 上下文设置](https://docs.ollama.com/context-length)、[Kokoro 模型说明](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)。
