# 使用说明

安装和启动见 [README](../README.md)。本页说明配置、播放策略和常见问题。

## 配置

仓库只保留 `config.json` 这一份运行配置，直接修改即可，无需复制模板。该文件随 Git 管理；修改后重启程序生效，相对路径以脚本所在目录为基准。

配置按 `llm` 和 `tts` 分组，后端专属参数放在 `tts.kokoro`、`tts.qwen3` 等子组。每组的 `desc` 集中说明用途、可选值及试听链接，不参与运行。JSON 不支持 `//` 注释，请保留双引号和逗号。

旧版平铺配置不再读取。更新前备份原文件，将原有值填入新版对应分组，不用旧文件整体覆盖新版配置。下表中的点号表示 JSON 层级，例如 `llm.model` 是 `llm` 对象中的 `model`。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `llm.url` | `http://127.0.0.1:11434/api/chat` | Ollama 对话接口 |
| `llm.model` | `qwen3.5:4b-q4_K_M` | 与 `ollama list` 中名称一致 |
| `llm.context_tokens` | `32768` | 32K 上下文；显存紧张可尝试 `16384` |
| `llm.max_output_tokens` | `4096` | 单次回答生成 token 数上限 |
| `tts.backend` | `qwen3` | `kokoro` 使用 CPU，`qwen3` 使用 CUDA GPU，`volcengine` 使用火山云端 |
| `tts.kokoro.model_dir` | `../kokoro-multi-lang-v1_1` | 已有 Kokoro 模型目录，与 localTalk 项目目录同级 |
| `tts.qwen3.model` | `../Qwen3-TTS-12Hz-0.6B-CustomVoice` | 与项目同级的 Qwen 模型目录，也支持模型 ID，仅 Qwen 后端使用 |
| `tts.qwen3.speaker` | `Serena` | Qwen 音色名称，仅 Qwen 后端使用 |
| `tts.kokoro.speaker_id` | `3` | 中文女声 `zf_001` |
| `tts.kokoro.speed` | `1.0` | 仅 Kokoro 使用，大于 1 更快，小于 1 更慢 |
| `tts.audio_output_dir` | `../output/segments` | 可复用 WAV 缓存目录，默认在仓库外，保留最近使用的 100 个不同片段 |
| `tts.startup_text` | `你好，我在，请问有什么可以帮你？` | 启动后朗读；空字符串关闭 |
| `tts.kokoro.threads` | `4` | CPU 合成线程数，可用相同文本比较 4 和 6 |
| `tts.chunk_chars` | `60` | 所有片段的最大长度，不得小于当前后端任一阶段的门槛 |
| `tts.<后端>.chunking.first_min_chars` | `11` | 首段遇标点可提交的最短长度 |
| `tts.<后端>.chunking.second_min_chars` | `20` | 第二段遇标点可提交的最短长度 |
| `tts.<后端>.chunking.later_min_chars` | `20` | 后续段按句尾优先规则提交的最短长度 |

火山后端另配置 `tts.volcengine.voice_id`、`api_key_env`、`language_code`、`sample_rate`、`timeout_seconds`，音色效果放在 `voice_settings` 子组。API Key 只存环境变量，完整步骤见 [火山接入说明](tts.md#火山-seed-tts-30-http-流式)。

模型目录需要包含 `model.onnx`、`voices.bin`、`tokens.txt`、`espeak-ng-data/`、`lexicon-us-en.txt` 和 `lexicon-zh.txt`，请保留解压包的完整内容。

上述文件清单及 `tts.kokoro.speaker_id`、`tts.kokoro.threads` 仅适用于 Kokoro。Qwen 安装和切换见 [TTS 选型与切换](tts.md)，不读取 Kokoro 模型文件。

### 音色与语速

本项目使用的 Kokoro v1.1 中，中文女声编号为 3～57，男声为 58～102。可用同一段文本、相同语速对比以下声音：

| 音色名称 | `tts.kokoro.speaker_id` | 类型 |
| --- | --- | --- |
| `zf_001` | `3` | 中文女声 |
| `zf_073` | `40` | 中文女声 |
| `zm_009` | `58` | 中文男声 |
| `zm_010` | `59` | 中文男声 |

完整映射与样例见 [sherpa-onnx 官方试听页](https://k2-fsa.github.io/sherpa/onnx/tts/all/Chinese-English/kokoro-multi-lang-v1_1.html)。音色名称中的数字不等于 `tts.kokoro.speaker_id`；以上顺序不是质量排名。Kokoro 当前未提供单独的情绪或音高控制。

### 上下文与输出

每次请求显式设置 `num_ctx` 和 `num_predict`，不依赖 Ollama 的默认窗口。发起一轮请求后，可观察实际分配：

```powershell
ollama ps
nvidia-smi
```

`ollama ps` 的 `CONTEXT` 表示分配窗口，`100% GPU` 表示模型完全加载到 GPU；显卡整体占用以 `nvidia-smi` 为参考。32K 窗口能加载不代表长输入的峰值占用和性能已经验证。

系统提示词、历史和本次问题共同占用输入预算，程序为输出上限另留空间。当前按 UTF-8 字节数加格式余量保守估算，超过预算时成对移除最早问答；这不是精确 tokenizer，可能早于实际窗口耗尽时裁剪。

当前关闭思考，不发送思考过程给 TTS。系统提示词和采样参数位于 `localtalk/ollama.py`，不同模型可能需要适配。模型回答达到输出上限时会提示可能未说完。

## 分段播放与延迟

所有后端共用大模型请求、流式解析和分段算法，只读取当前后端 `chunking` 的三个长度门槛。例如选择火山时使用 `tts.volcengine.chunking`；切换到 Qwen 时使用 `tts.qwen3.chunking`，Kokoro 同理。三个值均为正整数，且不超过全局上限 `tts.chunk_chars`。字符数按 Python 字符串长度计算，包含标点：

- 首段达到 `first_min_chars`（默认 11）后，遇到逗号、分号、冒号、句尾标点或换行即可立即提交；第二段使用 `second_min_chars`（默认 20），同样可沿普通标点提交。
- 第三段起使用 `later_min_chars`（默认 20），优先在句号、问号、感叹号或换行处分段；不足门槛的短句与后文合并。
- 超过 `tts.chunk_chars`（默认 60 字）仍没有合适句尾时，选择前 60 字内最后一个满足当前段最短长度的逗号、分号、冒号等普通标点或空白。
- 没有符合条件的边界时，按字符上限切分；最后不足当前门槛的尾段仍正常朗读。
- 前两段不额外等待标点后的字符，句尾引号可能位于下一片段开头；后续段尽量将句尾引号保留在原句。英文句点后接空白时识别为句尾。分段只取原文连续片段，不删除、重复或改写内容；朗读前会去除片段首尾空白，本地后端另沿用去除中文双引号的处理。

分段随大模型增量文本到达持续进行，不等待整篇回答。各段统一使用 60 字上限，不按上一段长度动态调整；网络包边界不作为切分点。首段更早提交可以缩短等待，但过短音频仍可能先播完再等待第二段，实际效果需试听。长句硬切仍可能影响语调。

一个工作线程顺序查缓存、合成音频，另一个工作线程顺序播放；当前片段播放期间准备下一段。音频队列最多缓冲 3 段，文本队列不设段数限制，单次回答仍受输出 token 上限约束。主线程收到文本立即打印，不等待语音；播放完成后才能输入下一问。

火山使用 HTTPS POST，一次提交一个完整文本片段，按 JSONL 事件流收取 MP3 音频；收到会话结束标记并收齐响应后解码播放。无需管理 WebSocket、文本发送线程或 `flush` 批次。每个片段仍需完整收齐后播放，并非逐音频帧播放。

此前串行原型在 i5-10600KF 上的一次故事测量：文本生成 5.95 秒，整篇合成 84.34 秒，音频 173.27 秒，首次播放约需等待 90 秒。合成实时率约为 0.49，说明该次平均合成速度快于播放速度；这不是分段版本的延迟测试结果。

分段可以提前准备首段音频，但不保证降低总合成量。很短的首段可能先播完，再等待下一段；设备波动也可能产生句间停顿。

### 运行指标与音频文件

文本接收完毕时立即显示文本接收耗时；本轮播放完成后显示首段文本、首段提交播放时间、播放段数、音频长度、缓存命中数及输入/输出 token 数。

本地后端另显示累计合成时间与新合成音频的实时率，缓存命中的音频不进入实时率分母。火山显示含网络等待的合成请求耗时，不将其标为本地合成实时率。

“片段间等待”统计上一段播放调用返回到下一段播放调用开始之间的累计时间和最长时间，包含等待合成、缓存读取与排队的开销，不包含音频本身的静音或设备缓冲。首段提交播放时间也不包含远程桌面和设备缓冲延迟。

### 音频缓存与复用

缓存键由实际送入 TTS 的文本、后端、模型、音色与可调整的声音参数生成，使用标准库 BLAKE2b 的 128 位摘要，文件名为 `segment-<32位十六进制摘要>.wav`，不另存原文索引。火山保留语种、采样率和 `voice_settings` 中的声音设置；固定编码、码率和文本处理开关不参与，密钥、超时、`desc` 和保存路径也不参与。固定合成设置或缓存格式变化时，通过缓存版本统一使旧缓存失效。

命中时直接播放已有 WAV，不重复合成，也不重复创建文件。未命中时，只有完整合成并成功解码的音频才通过临时文件写入、替换成正式缓存；中断或失败的 HTTP 音频不会落为有效缓存。缓存 WAV 的格式、帧数和数据长度会被检查，损坏文件按未命中重新合成。

一次 HTTPS 请求的完整音频对应一个缓存文件；响应中的多个音频包只拼接，不分别保存。缓存包含开场语，完整生成后即保存，不要求已经播放。保留最近使用的 100 个不同片段，命中时更新最近使用时间，写入新片段时淘汰最久未使用的文件；跨轮次和重启复用。分段门槛不参与缓存键；实际切出的文本和合成参数相同即可命中，不做语义相似匹配。

旧的时间戳文件和 SHA-256 摘要文件不参与新版匹配，仍可手动回听，也计入 100 条保留范围，后续自然淘汰。清理只处理本程序命名的 WAV，不删除其他文件；旧版 `last_reply.wav` 不计入。缓存目录不会自动迁移。

若在同一路径替换本地模型权重，或在同一个音色 ID 下重新训练声音，需要手动清理对应缓存目录；程序不读取整套模型文件计算哈希。

## 对话与中断

- 仅在完整接收回答并完成本轮播放后更新历史；失败时可能已经播出部分内容，但本轮不写入历史，也不自动重播。
- 历史只存在于内存，不提供摘要或长期记忆；退出后清空。
- 播放完才能输入下一问，不支持语音打断；`Ctrl+C` 会等待当前同步合成或播放结束，并非即时静音。
- TTS 朗读模型原话，不核验事实；开始播放后不能撤回已播出的内容。
- 终端文本和对话历史保留原文，分段与朗读输入处理不改写原回答。
- 火山发生鉴权、网络或解码错误时停止本轮，不自动重试，避免已经播放的内容重复；错误中保留请求标识便于排查，之前完整生成的缓存仍可保留。

## 常见问题

遇到安装或启动问题，可先运行 `..\.venv\Scripts\python.exe -m scripts.check_env` 汇总当前状态，检查范围见 [环境检查说明](tts.md#检查-gpu-与依赖)。

**找不到配置文件**：从仓库恢复项目根目录的 `config.json`，然后核对所选后端及模型目录。

**找不到模型文件**：Kokoro 检查 `tts.kokoro.model_dir`，避免多嵌套一层同名目录，并保留解压包的全部资源；Qwen 检查 `tts.qwen3.model`，确认已按 [TTS 部署说明](tts.md#模型目录)下载完整模型。

**火山启动或合成失败**：检查密钥环境变量、音色权限和网络。`scripts/check_env.py` 只确认配置和依赖，不验证云端密钥有效性或余额；断流会报错，不会把未收齐的尾音当作正常结束。

**Windows 解压提示找不到 bzip2**：使用 [TTS 部署说明](tts.md#模型目录)中的 Python `tarfile` 命令，无需系统额外安装 bzip2。

**远程桌面没有声音**：检查远程客户端的音频重定向设置和系统输出设备；打开 `tts.audio_output_dir` 指定目录中的 WAV 对比声音。

**听到毛刺或爆音**：先单独回听对应 WAV，再与终端实时播放对比。如果文件里也存在，继续核对输入文本、音色和模型；如果只在片段连接处或远程播放时出现，应先排查片段边界、播放设备和音频重定向。仅换模型不保证消除这些问题。

**音色没有变化**：确认修改的是当前运行项目的 `config.json`，修改后重启；Kokoro 修改 `tts.kokoro.speaker_id`，可对比女声 `3` 和男声 `58`；Qwen 修改 `tts.qwen3.speaker`，可对比 Serena 和 Uncle_Fu。

**出现 `OOV word skipped`**：词典前端遇到不认识的字符可能跳过。已处理此前发现的中文双引号；普通汉字也被跳过时，应检查模型、词典和实际文本，不要只隐藏日志。

**Ollama 连接失败或找不到模型**：确认后台服务运行且名称与 `ollama list` 一致。默认使用本机接口，无需开放到局域网。

参考：[Ollama Chat API](https://docs.ollama.com/api/chat)、[Ollama 上下文设置](https://docs.ollama.com/context-length)、[Kokoro 模型说明](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)。
